# WeatherTag 部署与运行手册

本文面向 Debian/Ubuntu 系的 Linux 家庭服务器，使用 BlueZ 蓝牙栈和 systemd 常驻运行 WeatherTag。部署后的目录与权限如下：

| 内容 | 路径 | 所有者 | 服务用户权限 |
| --- | --- | --- | --- |
| 代码和虚拟环境 | `/opt/weathertag` | `root:root` | 只读 |
| 配置和 JWT 私钥 | `/etc/weathertag` | `root:weathertag` | 只读 |
| 运行状态和最新图片 | `/var/lib/weathertag` | `weathertag:weathertag` | 读写 |
| systemd 单元 | `/etc/systemd/system/weathertag.service` | `root:root` | 只读 |

`weathertag` 是不可登录、无 `sudo` 权限的专用系统用户。不建议以 `root` 身份运行服务。

## 1. 部署前准备

硬件和账号要求：

- Linux 主机有可用的 BLE 适配器，外置天线已安装；
- 4.2 寸电子价签已刷入 EPD-nRF5 v1.6 或更新固件，屏幕驱动与引脚已在固件端配好；
- Python 3.11 或更高版本；
- 和风天气账号、项目、JWT 凭据和专属 API Host；
- 主机能通过 HTTPS 访问和风天气 API 和 Python 包索引。

下文命令默认当前管理员可以使用 `sudo`。请按顺序执行，不要把占位符原样写入生产配置。

## 2. 安装系统依赖

```bash
# 刷新软件包索引。
sudo apt update

# 安装 Git、Python 虚拟环境、BlueZ、蓝牙诊断工具、中文字体和密钥工具。
sudo apt install -y \
  ca-certificates \
  git \
  python3 \
  python3-pip \
  python3-venv \
  bluez \
  rfkill \
  fonts-wqy-zenhei \
  openssl

# WeatherTag 要求 Python >= 3.11；版本不足时应先升级系统 Python。
python3 --version

# 确认汉字字体存在。
test -f /usr/share/fonts/truetype/wqy/wqy-zenhei.ttc
```

如果 `pip` 在 ARM 或少见平台上需要从源码编译依赖，再安装下列构建工具；普通 x86-64/aarch64 有可用 wheel 时通常不需要：

```bash
# 仅在 pip 报编译错误时执行。
sudo apt install -y build-essential python3-dev libffi-dev libssl-dev cargo pkg-config
```

## 3. 启用蓝牙

```bash
# 启用 BlueZ 并设置开机启动。
sudo systemctl enable --now bluetooth

# 解除可能的软件射频屏蔽。
sudo rfkill unblock bluetooth

# 检查是否有控制器，Powered 应为 yes。
bluetoothctl list
bluetoothctl show

# 检查 BlueZ 服务状态。
systemctl status bluetooth --no-pager --full
```

如果 `bluetoothctl list` 没有输出，先处理 USB/PCIe 设备、内核驱动、BIOS 开关、`rfkill` 或天线问题，后续部署无法弥补系统看不到蓝牙控制器的问题。

## 4. 创建专用用户和目录

以下用户创建命令只在首次安装时执行一次：

```bash
# 创建不可交互登录的系统用户和同名用户组。
sudo useradd \
  --system \
  --user-group \
  --home-dir /nonexistent \
  --shell /usr/sbin/nologin \
  weathertag

# 加入蓝牙设备组。BlueZ 的 D-Bus 策略仍是最终权限来源。
sudo usermod --append --groups bluetooth weathertag

# 创建配置目录和运行数据目录。
sudo install -d -o root -g weathertag -m 0750 /etc/weathertag
sudo install -d -o weathertag -g weathertag -m 0750 /var/lib/weathertag

# 检查用户、用户组及目录权限。
getent passwd weathertag
id weathertag
ls -ld /etc/weathertag /var/lib/weathertag
```

不要给 `weathertag` 账号设置密码，也不要把它加入 `sudo` 组。

## 5. 获取代码并创建虚拟环境

```bash
# 将 main 分支克隆到固定生产路径。
sudo git clone \
  --branch main \
  --single-branch \
  https://git.h.ybts.xyz/admin/weathertag.git \
  /opt/weathertag

# 代码由 root 管理，服务用户不应修改程序。
sudo chown -R root:root /opt/weathertag
sudo chmod -R go-w /opt/weathertag

# 创建独立 Python 环境并安装项目。
sudo python3 -m venv /opt/weathertag/.venv
sudo /opt/weathertag/.venv/bin/python -m pip install --upgrade pip
sudo /opt/weathertag/.venv/bin/python -m pip install --editable /opt/weathertag

# 检查 CLI 和 Python 版本。
/opt/weathertag/.venv/bin/python --version
/opt/weathertag/.venv/bin/weathertag --help
```

如果 Git 仓库需要认证，使用只读部署凭据或 Git credential helper。不要把访问令牌直接写入命令 URL、文档或 `config.toml`。

## 6. 生成和风天气 JWT 密钥

```bash
# 生成 Ed25519 私钥和公钥。
sudo openssl genpkey \
  -algorithm ED25519 \
  -out /etc/weathertag/ed25519-private.pem

sudo openssl pkey \
  -pubout \
  -in /etc/weathertag/ed25519-private.pem \
  -out /etc/weathertag/ed25519-public.pem

# 私钥仅 root 和 weathertag 组可读；公钥可公开读取。
sudo chown root:weathertag /etc/weathertag/ed25519-private.pem
sudo chmod 0640 /etc/weathertag/ed25519-private.pem
sudo chown root:root /etc/weathertag/ed25519-public.pem
sudo chmod 0644 /etc/weathertag/ed25519-public.pem

# 输出公钥，将完整内容添加到和风天气控制台的 JWT 凭据。
sudo cat /etc/weathertag/ed25519-public.pem
```

在和风天气控制台完成以下操作：

1. 把上述公钥添加为 JWT 凭据；
2. 记录项目 ID（Project ID）和凭据 ID（Credential ID）；
3. 在控制台“设置”中记录专属 API Host；
4. 确认经纬度，经度在前、纬度在后。

## 7. 创建生产配置

```bash
# 从示例创建生产配置。
sudo install \
  -o root \
  -g weathertag \
  -m 0640 \
  /opt/weathertag/config.example.toml \
  /etc/weathertag/config.toml

# 使用安全的管理员编辑方式修改配置。
sudoedit /etc/weathertag/config.toml
```

首次配置建议先保持 `ble.enabled = false`，完成 API 和渲染验证后再开启 BLE。参考配置如下：

```toml
[app]
state_path = "/var/lib/weathertag/state.json"
output_path = "/var/lib/weathertag/latest.png"
log_level = "INFO"

[qweather]
# 不要写 https://；填控制台显示的专属 Host。
api_host = "YOUR_HOST.qweatherapi.com"
project_id = "YOUR_PROJECT_ID"
credential_id = "YOUR_CREDENTIAL_ID"
private_key_path = "/etc/weathertag/ed25519-private.pem"
longitude = 116.41
latitude = 39.92
language = "zh"
timeout_seconds = 15
retry_attempts = 3

[ble]
# 首次验证 API 时保持 false；扫描并填写设备后改为 true。
enabled = false
address = ""
name = ""
connect_timeout_seconds = 20
retry_attempts = 3
write_ack_interval = 20
# 三色屏刷新期间保持 BLE 连接，避免图像发淡或刷新不完整。
refresh_wait_seconds = 25

[gotify]
enabled = false
base_url = "https://push.example.com"
token = ""
priority = 7
timeout_seconds = 10
cooldown_minutes = 360

[schedule]
poll_minutes = 10
morning_minutes = 30
daytime_minutes = 60
evening_minutes = 30
overnight_minutes = 120

[rules]
rain_threshold_mm = 0.01
high_temperature_c = 35
cold_temperature_c = 5
temperature_gap_c = 10
significant_temperature_change_c = 2
hourly_rain_probability = 50

[render]
width = 400
height = 300
font_path = "/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc"
```

如果启用 Gotify，将 `enabled` 改为 `true`，并填写服务地址和应用 Token。保持配置文件为 `0640 root:weathertag`，因为其中可能包含 Gotify Token。

## 8. 以服务用户完成首次验证

此阶段故意使用 `sudo -u weathertag`，以验证未来 systemd 进程实际拥有的文件和蓝牙权限。

```bash
# 检查 TOML、必填项、字体和 JWT 私钥。
sudo -u weathertag -- \
  /opt/weathertag/.venv/bin/weathertag \
  validate-config \
  --config /etc/weathertag/config.toml

# BLE 关闭时执行一次：获取天气并生成 PNG，不刷新硬件。
sudo -u weathertag -- \
  /opt/weathertag/.venv/bin/weathertag \
  run-once \
  --config /etc/weathertag/config.toml \
  --force

# 确认状态和图片已由专用用户生成。
ls -l /var/lib/weathertag/state.json /var/lib/weathertag/latest.png
file /var/lib/weathertag/latest.png
```

预期第一条命令输出“配置有效”，第二条命令退出码为 `0`，并生成 400×300 PNG。

## 9. 扫描和联调 BLE 电子价签

先关闭官方网页工具或其他已连接价签的客户端，把价签放在主机附近，再扫描：

```bash
# 必须以实际服务用户扫描，不要只用 root 测试。
sudo -u weathertag -- \
  /opt/weathertag/.venv/bin/weathertag \
  scan-ble \
  --timeout 15
```

输出格式是“设备地址 + Tab + 广播名称”。Linux 上优先填写稳定的 `address`，也可以用 `name`。修改配置：

```toml
[ble]
enabled = true
address = "AA:BB:CC:DD:EE:FF"
name = ""
connect_timeout_seconds = 20
retry_attempts = 3
write_ack_interval = 20
refresh_wait_seconds = 25
```

然后强制刷新真机：

```bash
# 再次检查开启 BLE 后的配置。
sudo -u weathertag -- \
  /opt/weathertag/.venv/bin/weathertag \
  validate-config \
  --config /etc/weathertag/config.toml

# 获取天气、传输黑/白/红位面并等待电子墨水屏完成刷新。
sudo -u weathertag -- \
  /opt/weathertag/.venv/bin/weathertag \
  run-once \
  --config /etc/weathertag/config.toml \
  --force
```

三色屏完整刷新会有明显的闪烁阶段。`refresh_wait_seconds = 25` 会在发送刷新命令后继续保持 BLE 连接；若闪烁时间明显短于官方工具、图像发淡或刷新不完整，先确认该值没有被改小。

当固件返回 `bat=2987` 时，程序会将其记录为 2987 mV，并在下一次渲染时在右上角显示 `2.99V`。首次刷新还没有历史读数时显示 `--.--V` 是正常的。

## 10. 安装并启动 systemd 服务

```bash
# 安装仓库自带的 systemd 单元。
sudo install \
  -o root \
  -g root \
  -m 0644 \
  /opt/weathertag/deploy/weathertag.service \
  /etc/systemd/system/weathertag.service

# 让 systemd 重新读取单元，并立即启动。
sudo systemctl daemon-reload
sudo systemctl enable --now weathertag

# 检查服务状态和最近 100 行日志。
sudo systemctl status weathertag --no-pager --full
sudo journalctl -u weathertag -n 100 --no-pager

# 确认单元实际使用专用账号。
sudo systemctl show weathertag --property=User --property=Group --property=MainPID
```

服务启动后会每 10 分钟轮询天气，但只在发生重要变化或达到当前时段的常规刷屏间隔时更新价签。

## 11. 日常运行命令

```bash
# 查看当前状态。
sudo systemctl status weathertag --no-pager --full

# 实时跟踪日志；按 Ctrl+C 退出日志视图，不会停止服务。
sudo journalctl -u weathertag -f

# 查看本次开机以来的全部日志。
sudo journalctl -u weathertag -b --no-pager

# 重启、停止和启动服务。
sudo systemctl restart weathertag
sudo systemctl stop weathertag
sudo systemctl start weathertag

# 手工强制刷屏前，先停服务以避免两个 BLE 客户端并发连接。
sudo systemctl stop weathertag
sudo -u weathertag -- \
  /opt/weathertag/.venv/bin/weathertag \
  run-once \
  --config /etc/weathertag/config.toml \
  --force
sudo systemctl start weathertag
```

修改 `/etc/weathertag/config.toml` 后，先运行 `validate-config`，再重启服务。

## 12. 升级

升级前先记录当前提交，便于必要时回滚：

```bash
# 停止服务并记录升级前版本。
sudo systemctl stop weathertag
sudo git -C /opt/weathertag rev-parse HEAD

# 仅允许快进更新，避免在服务器上自动生成合并提交。
sudo git -C /opt/weathertag fetch --prune origin
sudo git -C /opt/weathertag pull --ff-only origin main

# 重新安装，以应用新增或变更的依赖和命令行入口。
sudo /opt/weathertag/.venv/bin/python -m pip install --editable /opt/weathertag

# 运行无需 API/BLE 的测试，然后验证生产配置。
cd /opt/weathertag
sudo /opt/weathertag/.venv/bin/python -m unittest discover -v
sudo -u weathertag -- \
  /opt/weathertag/.venv/bin/weathertag \
  validate-config \
  --config /etc/weathertag/config.toml

# 重新启动并检查日志。
sudo systemctl start weathertag
sudo systemctl status weathertag --no-pager --full
sudo journalctl -u weathertag -n 100 --no-pager
```

不要在 `/opt/weathertag` 直接修改生产代码；这会阻止 `git pull --ff-only` 或使部署结果无法复现。界面微调应在开发工作区修改 `weathertag/renderer.py` 顶部的 `LAYOUT`，测试后提交、推送，最后按上述流程升级生产机。

## 13. 回滚

下列 `<KNOWN_GOOD_COMMIT>` 必须替换为升级前记录的完整提交 ID。回滚不删除配置和状态数据。

```bash
# 暂停服务，切到已知正常的提交并重新安装。
sudo systemctl stop weathertag
sudo git -C /opt/weathertag switch --detach <KNOWN_GOOD_COMMIT>
sudo /opt/weathertag/.venv/bin/python -m pip install --editable /opt/weathertag

# 检查配置后恢复服务。
sudo -u weathertag -- \
  /opt/weathertag/.venv/bin/weathertag \
  validate-config \
  --config /etc/weathertag/config.toml
sudo systemctl start weathertag
sudo journalctl -u weathertag -n 100 --no-pager
```

问题解决后回到 `main` 并升级：

```bash
sudo systemctl stop weathertag
sudo git -C /opt/weathertag switch main
sudo git -C /opt/weathertag pull --ff-only origin main
sudo /opt/weathertag/.venv/bin/python -m pip install --editable /opt/weathertag
sudo systemctl start weathertag
```

## 14. 备份

至少备份 `/etc/weathertag`。其中的 Ed25519 私钥与和风天气凭据绑定，丢失后需重建凭据。`/var/lib/weathertag` 可选备份，包含最后状态、电池读数和最新 PNG。

```bash
# 请将 YYYYMMDD 替换为实际日期，备份文件仅 root 可读。
sudo tar \
  --create \
  --gzip \
  --file /root/weathertag-backup-YYYYMMDD.tar.gz \
  --directory / \
  etc/weathertag \
  var/lib/weathertag
sudo chmod 0600 /root/weathertag-backup-YYYYMMDD.tar.gz
```

## 15. 常见故障

### 配置或私钥无法读取

```bash
# 逐级查看路径权限。
namei -l /etc/weathertag/config.toml
namei -l /etc/weathertag/ed25519-private.pem

# 以服务用户实测读取与 JWT 生成，不要只看 root 的结果。
sudo -u weathertag -- \
  /opt/weathertag/.venv/bin/weathertag \
  validate-config \
  --config /etc/weathertag/config.toml
```

应确保目录为 `0750 root:weathertag`，配置和私钥为 `0640 root:weathertag`。

### 扫描不到设备

```bash
# 检查控制器、射频屏蔽、BlueZ 和专用用户的组。
bluetoothctl list
bluetoothctl show
rfkill list bluetooth
systemctl status bluetooth --no-pager --full
id weathertag

# 在更长窗口内以服务用户重试。
sudo -u weathertag -- \
  /opt/weathertag/.venv/bin/weathertag \
  scan-ble \
  --timeout 30
```

同时检查：蓝牙/Wi-Fi 天线是否安装、价签是否在广播、距离是否过远，以及官方网页或手机是否仍占用连接。

### `org.bluez.Error.NotAuthorized`

先确认实际出错命令是否以 `weathertag` 用户运行。BlueZ 上游默认 system bus 策略允许向 `org.bluez` 发送请求，但发行版可能有自定义策略。

```bash
# 查看本机 BlueZ D-Bus 策略，不要盲目复制全局放行规则。
sudo less /usr/share/dbus-1/system.d/bluetooth.conf

# 查看 BlueZ 和服务同期日志。
sudo journalctl -u bluetooth -u weathertag -b --no-pager
```

仅在确认发行版策略拒绝相关方法后，才按该发行版的官方方式添加最小化授权。不建议通过允许任意用户访问任意 D-Bus 服务来规避问题。

### BLE 连接 `TimeoutError`

这表示已找到设备，但在限时内没有建立 GATT 连接。常见原因是天线未安装或信号弱、设备正被其他客户端连接、地址填错、价签未处于可连接状态。先重新 `scan-ble`，再在近距离下重试；必要时将 `connect_timeout_seconds` 从 `20` 调到 `30`。

### 屏幕可以写入，但图像很淡

优先确认 `refresh_wait_seconds = 25`。BLE 的 GATT 写入确认只表示固件收到 `REFRESH` 命令，不代表电子墨水屏已跑完物理刷新波形。过早断开可能使部分异步刷新固件提前休眠，表现为闪烁过短、图像发淡。

如果等待 25 秒仍有问题，用官方网页工具发送同一张 `/var/lib/weathertag/latest.png`。官方工具也不正常时，检查固件屏幕驱动、引脚、电池和面板；官方工具正常而 WeatherTag 不正常时，保留完整日志并对比刷新持续时间。

### systemd 不断重启

```bash
# 先查看第一个实际异常，不要只看最后的 restart 提示。
sudo journalctl -u weathertag -b -n 300 --no-pager

# 停止循环重启，手工验证配置。
sudo systemctl stop weathertag
sudo -u weathertag -- \
  /opt/weathertag/.venv/bin/weathertag \
  validate-config \
  --config /etc/weathertag/config.toml
```

修复后执行 `sudo systemctl start weathertag`。

## 16. 安全检查清单

- `weathertag` 是 `nologin` 用户，不在 `sudo` 组；
- `/opt/weathertag` 由 `root:root` 所有，其他用户无写权限；
- `/etc/weathertag/config.toml` 和私钥为 `0640 root:weathertag`；
- 私钥、Gotify Token 和 Git 令牌没有进入 Git 历史；
- systemd 单元使用 `User=weathertag`、`ProtectSystem=strict`、`ProtectHome=true`、`NoNewPrivileges=true`；
- 只有 `/var/lib/weathertag` 对服务进程可写；
- 真机扫描和 `run-once` 都已用 `sudo -u weathertag` 验证。
