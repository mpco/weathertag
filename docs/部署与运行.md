# WeatherTag LXC 部署与运行

本文面向单用 Debian/Ubuntu LXC，默认容器内使用 `root` 账号。代码、虚拟环境、配置、密钥、状态和最新图片都保留在 `/root/weathertag` 项目目录，不再拆分到 `/etc/weathertag` 和 `/var/lib/weathertag`。

```text
/root/weathertag/
├── .venv/                         # Python 虚拟环境
├── config.toml                   # 实际配置，已被 Git 忽略
├── secrets/
│   ├── ed25519-private.pem       # 和风天气 JWT 私钥
│   └── ed25519-public.pem        # 上传到和风天气的公钥
├── var/
│   ├── state.json                # 运行状态
│   └── latest.png                # 最新渲染图片
└── deploy/weathertag.service      # systemd 单元源文件
```

## 1. LXC 前置条件

WeatherTag 通过 BlueZ D-Bus 访问蓝牙。容器中必须能看到宿主机暴露的 system bus socket：

```text
/bt-dbus/system_bus_socket
```

本文假定该 socket 已由宿主机正确提供。如果条件允许，优先使用只允许 BlueZ 的受限 D-Bus 代理端点。直接把宿主机完整 `/run/dbus` 暴露给容器虽然简单，但会让容器看到宿主机 system bus；即使文件系统挂载为只读，可调用的 D-Bus 方法仍由宿主机 D-Bus 策略决定。请只对可信、用途单一的 LXC 这样做。

如果使用直接挂载，挂载 D-Bus 目录通常比只挂载单个 socket 文件稳定，因为 D-Bus 重启后可能重建 socket。具体 LXC 挂载方式由宿主机管理工具决定。

```bash
# 必须输出“D-Bus socket 存在”。
if test -S /bt-dbus/system_bus_socket; then
  echo "D-Bus socket 存在"
else
  echo "错误：未找到 /bt-dbus/system_bus_socket"
fi
```

### D-Bus 环境变量的正确格式

`DBUS_SYSTEM_BUS_ADDRESS` 接受的是“D-Bus 地址”，不是纯文件路径。当前 Bleak 使用的 `dbus-fast` 要求地址包含 transport，因此需要加上 `unix:path=`：

```bash
# 正确：完整 D-Bus 地址。
export DBUS_SYSTEM_BUS_ADDRESS='unix:path=/bt-dbus/system_bus_socket'

# 错误：这只是文件路径，会报缺少 transport。
# export DBUS_SYSTEM_BUS_ADDRESS='/bt-dbus/system_bus_socket'
```

手工命令使用当前 shell 中的 `export`；systemd 单元已内置同样的环境变量，无需修改 shell 配置文件。

## 2. 安装系统依赖

```bash
# 更新包索引并安装必要软件。
apt update
apt install -y \
  ca-certificates \
  git \
  python3 \
  python3-pip \
  python3-venv \
  dbus \
  fonts-wqy-zenhei \
  openssl

# WeatherTag 要求 Python >= 3.11。
python3 --version

# 确认渲染使用的中文字体存在。
test -f /usr/share/fonts/truetype/wqy/wqy-zenhei.ttc
```

容器通过宿主机的 D-Bus 访问 BlueZ，通常不需要在容器内启动另一个 `bluetooth.service`，也不需要把蓝牙 USB 设备直通给容器。

如果 `pip` 报依赖编译错误，再安装：

```bash
# 只有从源码构建 Python 依赖时才需要。
apt install -y build-essential python3-dev libffi-dev libssl-dev cargo pkg-config
```

## 3. 克隆并安装 WeatherTag

```bash
# 以 root 登录 LXC 后，克隆到默认路径。
cd /root
git clone https://git.h.ybts.xyz/admin/weathertag.git
cd /root/weathertag

# 所有 Python 依赖都安装在项目内的 .venv。
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install --editable .

# 创建项目内的配置、密钥和状态目录。
mkdir -p secrets var
cp config.example.toml config.toml
chmod 0700 secrets
chmod 0600 config.toml

# 确认 CLI 可用。
.venv/bin/weathertag --help
```

`.venv/`、`config.toml`、`secrets/` 和 `var/` 已在 `.gitignore` 中，不会被正常的 `git add` 加入仓库。

## 4. 生成和风天气 JWT 密钥

```bash
cd /root/weathertag

# 在项目内生成 Ed25519 私钥和公钥。
openssl genpkey \
  -algorithm ED25519 \
  -out secrets/ed25519-private.pem

openssl pkey \
  -pubout \
  -in secrets/ed25519-private.pem \
  -out secrets/ed25519-public.pem

# 仅 root 可读私钥。
chmod 0600 secrets/ed25519-private.pem

# 将输出的完整公钥添加到和风天气控制台。
cat secrets/ed25519-public.pem
```

然后在和风天气控制台记录项目 ID、JWT 凭据 ID、专属 API Host，以及要查询位置的经纬度（经度在前、纬度在后）。

## 5. 编辑配置

```bash
cd /root/weathertag
nano config.toml
```

`config.example.toml` 默认已使用项目内相对路径，不要改成 `/etc/weathertag` 或 `/var/lib/weathertag`：

```toml
[app]
state_path = "var/state.json"
output_path = "var/latest.png"
log_level = "INFO"

[qweather]
api_host = "YOUR_HOST.qweatherapi.com"
project_id = "YOUR_PROJECT_ID"
credential_id = "YOUR_CREDENTIAL_ID"
private_key_path = "secrets/ed25519-private.pem"
longitude = 116.41
latitude = 39.92
language = "zh"
timeout_seconds = 15
retry_attempts = 3

[ble]
# 先保持 false，验证天气 API 后再扫描设备。
enabled = false
address = ""
name = ""
connect_timeout_seconds = 20
retry_attempts = 3
write_ack_interval = 20
# 保持连接直到三色屏完成物理刷新。
refresh_wait_seconds = 25

[gotify]
enabled = false
base_url = "https://push.example.com"
token = ""
priority = 7
timeout_seconds = 10
cooldown_minutes = 360

[schedule]
poll_minutes = 10
morning_minutes = 30
daytime_minutes = 60
evening_minutes = 30
overnight_minutes = 120

[rules]
rain_threshold_mm = 0.01
high_temperature_c = 35
cold_temperature_c = 5
temperature_gap_c = 10
significant_temperature_change_c = 2
hourly_rain_probability = 50

[render]
width = 400
height = 300
font_path = "/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc"
```

如果启用 Gotify，填写 `base_url` 和应用 Token 后再将 `enabled` 改为 `true`。

## 6. 检查 D-Bus 并扫描 BLE

```bash
cd /root/weathertag
export DBUS_SYSTEM_BUS_ADDRESS='unix:path=/bt-dbus/system_bus_socket'

# 检查 socket 类型和权限。
ls -l /bt-dbus/system_bus_socket
test -S /bt-dbus/system_bus_socket

# 检查容器能否通过该 socket 看到 org.bluez。
busctl --address="$DBUS_SYSTEM_BUS_ADDRESS" --no-pager list | grep org.bluez

# 扫描 15 秒；预期输出“蓝牙地址 + 广播名称”。
.venv/bin/weathertag scan-ble --timeout 15
```

扫描前关闭官方网页工具或其他正在连接价签的客户端，并确保宿主机的蓝牙/Wi-Fi 天线已安装。

如果 `busctl` 能找到 `org.bluez`，但 `scan-ble` 没有结果，再检查价签广播状态、距离、天线和是否被其他客户端占用。

## 7. 首次运行

先在 BLE 关闭时验证配置和天气 API：

```bash
cd /root/weathertag
export DBUS_SYSTEM_BUS_ADDRESS='unix:path=/bt-dbus/system_bus_socket'

# 检查 TOML、字体和 JWT 私钥。
.venv/bin/weathertag validate-config --config config.toml

# BLE 关闭时只生成 var/latest.png，不刷新价签。
.venv/bin/weathertag run-once --config config.toml --force

# 确认产物位于项目内。
ls -l var/state.json var/latest.png
file var/latest.png
```

然后把 `scan-ble` 获得的地址或名称写入 `config.toml`：

```toml
[ble]
enabled = true
address = "AA:BB:CC:DD:EE:FF"
name = ""
connect_timeout_seconds = 20
retry_attempts = 3
write_ack_interval = 20
refresh_wait_seconds = 25
```

强制刷新真机：

```bash
cd /root/weathertag
export DBUS_SYSTEM_BUS_ADDRESS='unix:path=/bt-dbus/system_bus_socket'
.venv/bin/weathertag validate-config --config config.toml
.venv/bin/weathertag run-once --config config.toml --force
```

三色屏刷新时会明显闪烁。`refresh_wait_seconds = 25` 用于在发送 `REFRESH` 后继续保持 BLE 连接；如果闪烁时间明显短于官方工具、图像很淡或刷新不完整，先确认此值没有被改小。

## 8. systemd 常驻运行

仓库中的 `deploy/weathertag.service` 默认使用 `/root/weathertag`、容器内 `root`、项目内 `config.toml` 和 `/bt-dbus/system_bus_socket`。

安装时使用 `systemctl link`，单元源文件仍保留在项目目录：

```bash
cd /root/weathertag

# 检查单元文件语法。
systemd-analyze verify /root/weathertag/deploy/weathertag.service

# 在 systemd 搜索路径中创建指向项目内单元的链接。
systemctl link /root/weathertag/deploy/weathertag.service
systemctl daemon-reload
systemctl enable --now weathertag

# 检查服务状态和日志。
systemctl status weathertag --no-pager --full
journalctl -u weathertag -n 100 --no-pager
```

如果项目不在 `/root/weathertag`，先修改单元中的 `WorkingDirectory`、`ExecStart` 和 `ReadWritePaths`，再执行 `systemctl link`。

### 常用管理命令

```bash
# 实时日志；Ctrl+C 只退出日志视图。
journalctl -u weathertag -f

# 查看状态，或重启/停止/启动服务。
systemctl status weathertag --no-pager --full
systemctl restart weathertag
systemctl stop weathertag
systemctl start weathertag

# 手工刷屏前先停常驻服务，避免并发 BLE 连接。
systemctl stop weathertag
cd /root/weathertag
export DBUS_SYSTEM_BUS_ADDRESS='unix:path=/bt-dbus/system_bus_socket'
.venv/bin/weathertag run-once --config config.toml --force
systemctl start weathertag
```

## 9. 升级和回滚

### 升级

```bash
systemctl stop weathertag
cd /root/weathertag

# 记录升级前的提交 ID。
git rev-parse HEAD

# 仅允许快进更新，然后更新 Python 依赖。
git pull --ff-only origin main
.venv/bin/python -m pip install --editable .

# 测试不需要天气密钥或 BLE 硬件。
.venv/bin/python -m unittest discover -v
.venv/bin/weathertag validate-config --config config.toml

systemctl start weathertag
systemctl status weathertag --no-pager --full
```

### 回滚

将 `<KNOWN_GOOD_COMMIT>` 替换为升级前记录的完整提交 ID：

```bash
systemctl stop weathertag
cd /root/weathertag
git switch --detach <KNOWN_GOOD_COMMIT>
.venv/bin/python -m pip install --editable .
.venv/bin/weathertag validate-config --config config.toml
systemctl start weathertag
```

问题解决后回到主分支：

```bash
systemctl stop weathertag
cd /root/weathertag
git switch main
git pull --ff-only origin main
.venv/bin/python -m pip install --editable .
systemctl start weathertag
```

## 10. 备份

`config.toml` 可能包含 Gotify Token，`secrets/ed25519-private.pem` 与和风天气凭据绑定，备份应只允许 root 读取。

```bash
cd /root/weathertag

# 将 YYYYMMDD 替换为实际日期。
tar \
  --create \
  --gzip \
  --file /root/weathertag-backup-YYYYMMDD.tar.gz \
  config.toml \
  secrets \
  var
chmod 0600 /root/weathertag-backup-YYYYMMDD.tar.gz
```

## 11. 常见故障

### D-Bus socket 不存在

```bash
ls -ld /bt-dbus
ls -l /bt-dbus/system_bus_socket
test -S /bt-dbus/system_bus_socket
```

如果第三条失败，问题在 LXC 挂载或宿主机 D-Bus，尚未进入 WeatherTag/BLE 阶段。

### `InvalidAddressError: address did not contain a transport`

环境变量少了 `unix:path=`。修正为：

```bash
export DBUS_SYSTEM_BUS_ADDRESS='unix:path=/bt-dbus/system_bus_socket'
```

### 找不到 `org.bluez`

```bash
export DBUS_SYSTEM_BUS_ADDRESS='unix:path=/bt-dbus/system_bus_socket'
busctl --address="$DBUS_SYSTEM_BUS_ADDRESS" --no-pager list | grep org.bluez
```

检查宿主机 `bluetooth.service` 是否运行、挂载是否指向正确的 system bus，以及宿主机 BlueZ D-Bus 策略是否允许容器连接。

### BLE `TimeoutError`

这表示已找到设备，但在限时内没有建立 GATT 连接。常见原因是宿主机天线未安装或信号弱、价签正被官方网页/手机连接、BLE 地址填错。先重新 `scan-ble --timeout 30`，再在近距离下重试。

### 屏幕图像很淡

检查 `refresh_wait_seconds = 25`。GATT 写入成功只表示固件收到 `REFRESH` 命令，不代表屏幕已完成物理刷新。过早断连可能使固件提前休眠，表现为闪烁过短或图像发淡。

### systemd 启动失败

```bash
# 查看日志和 systemd 实际读到的环境变量。
journalctl -u weathertag -b -n 200 --no-pager
systemctl show weathertag --property=Environment

# 手工执行同等命令来分离配置、D-Bus 和 systemd 问题。
cd /root/weathertag
export DBUS_SYSTEM_BUS_ADDRESS='unix:path=/bt-dbus/system_bus_socket'
.venv/bin/weathertag validate-config --config config.toml
.venv/bin/weathertag run-once --config config.toml --force
```

## 12. 是否需要专用用户

对只运行 WeatherTag、由 LXC 提供隔离的家庭容器，使用容器内 `root` 是最简单的部署方式，也避免了 D-Bus socket 和项目文件的用户权限配置。

如果该容器还运行其他网络服务、允许其他人登录，或对进程隔离有更高要求，再创建专用用户。此时不应把项目放在通常为 `0700` 的 `/root` 下，可将整个项目克隆到 `/opt/weathertag` 或 `/srv/weathertag`，仍然把 `config.toml`、`secrets/` 和 `var/` 保留在项目中，然后同步修改 systemd 单元的 `User`、`Group`、`WorkingDirectory`、`ExecStart` 和 `ReadWritePaths`。
